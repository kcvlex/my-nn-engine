# Running the LLM benchmarks

The end-to-end orchestrator is `cargo run --release -p bench-llm`. It expects
three things to exist on disk; build them once and you can re-run forever.
Results are written to `bench/llm/results/SUMMARY.md`; copy the table into
[`docs/BENCHMARKS.md`](../docs/BENCHMARKS.md) when you want to publish.

## 0. Models
The bench binaries look at `models/hf/{tinyllama,llama2-7b-sft}` under the
repo. In a worktree, symlink them in:

```sh
ln -s /path/to/tinyllama       models/hf/tinyllama
ln -s /path/to/llama2-7b-sft   models/hf/llama2-7b-sft
```

Each dir needs `config.json`, `tokenizer.json`, and `model.safetensors` (BF16);
the INT8 file `model.int8.safetensors` is auto-generated by my-nn-engine on
first run if missing.

## 1. my-nn-engine bench binary
```sh
cargo build --release -p my-nn-engine-llm --example bench_llm
```

Env vars (set by `bench-llm` for each row): `BENCH_MODEL_DIR`, `BENCH_LABEL`,
`BENCH_DTYPE` (`bf16`|`int8`), `BENCH_N_GENERATE`, `BENCH_WARMUP`,
`BENCH_ITERS`, `BENCH_PROMPT`, `BENCH_MAX_SEQ_LEN`, `BENCH_PREFILL_LEN`
(set to `0` for decode-only models like Llama2-7B), `BENCH_AUTO_QUANT`
(`1` to auto-create `model.int8.safetensors` when missing). Output is
`BENCH_INFO` / `BENCH_ITER` lines.

## 2. llama.cpp baseline (CUDA, sm_89)
```sh
git clone https://github.com/ggerganov/llama.cpp ~/baselines/llama.cpp
cmake -B ~/baselines/llama.cpp/build \
      -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=89 -DLLAMA_CURL=OFF \
      -S ~/baselines/llama.cpp
cmake --build ~/baselines/llama.cpp/build --config Release -j 16 \
      --target llama-cli llama-bench llama-quantize

# HF → GGUF: hide the int8 safetensors so the converter doesn't choke on its
# extra scale tensors.
mkdir -p /tmp/tinyllama-clean /tmp/llama2-clean
for f in config.json generation_config.json model.safetensors \
         special_tokens_map.json tokenizer_config.json tokenizer.json \
         chat_template.jinja; do
    ln -sf "$(realpath models/hf/tinyllama/$f)" /tmp/tinyllama-clean/$f
done
for f in config.json model-*.safetensors model.safetensors.index.json \
         special_tokens_map.json tokenizer_config.json tokenizer.json; do
    ln -sf "$(realpath models/hf/llama2-7b-sft/$f)" /tmp/llama2-clean/$f
done

python -m venv /tmp/llamacpp-venv
/tmp/llamacpp-venv/bin/pip install "torch>=2.9" "numpy>=1.26" "sentencepiece>=0.2" \
    "transformers>=4.45,<5" "gguf>=0.17" "protobuf>=4"

mkdir -p ~/baselines/gguf
for m in tinyllama llama2-7b-sft; do
    /tmp/llamacpp-venv/bin/python ~/baselines/llama.cpp/convert_hf_to_gguf.py \
        /tmp/${m%-sft}-clean \
        --outfile ~/baselines/gguf/${m}-f16.gguf --outtype f16
    ~/baselines/llama.cpp/build/bin/llama-quantize \
        ~/baselines/gguf/${m}-f16.gguf \
        ~/baselines/gguf/${m}-q8_0.gguf Q8_0
done
```

`bench-llm` reads `$LLAMACPP_BIN` (default `~/baselines/llama.cpp/build/bin`)
and `$GGUF_DIR` (default `~/baselines/gguf`).

## 3. ORT-GenAI baseline (containerised)
ORT-GenAI's prebuilt CUDA wheels expect Python 3.10–3.12 and CUDA 12; the host
here runs Python 3.14 with CUDA 13. We sidestep that by running ORT-GenAI in a
podman container based on `bench/ortgenai/Dockerfile` (CUDA 12.6.3 + Python 3.10
+ `onnxruntime-genai-cuda`).

```sh
# Build container (one-time).
podman build -t ortgenai-bench bench/ortgenai/

# Convert HF → ORT-GenAI model dirs (uses CPU; runs in a venv).
python -m venv /tmp/ortgenai-venv
/tmp/ortgenai-venv/bin/pip install onnxruntime-genai-cuda transformers torch \
    sentencepiece onnx_ir

mkdir -p ~/baselines/ortgenai
/tmp/ortgenai-venv/bin/python -m onnxruntime_genai.models.builder \
    -i /tmp/tinyllama-clean -o ~/baselines/ortgenai/tinyllama-fp16 \
    -p fp16 -e cuda -c /tmp/ortgenai-cache
/tmp/ortgenai-venv/bin/python -m onnxruntime_genai.models.builder \
    -i /tmp/tinyllama-clean -o ~/baselines/ortgenai/tinyllama-int4 \
    -p int4 -e cuda -c /tmp/ortgenai-cache
/tmp/ortgenai-venv/bin/python -m onnxruntime_genai.models.builder \
    -i /tmp/llama2-clean -o ~/baselines/ortgenai/llama2-7b-int4 \
    -p int4 -e cuda -c /tmp/ortgenai-cache
```

`bench-llm` reads `$ORTGENAI_DIR` (default `~/baselines/ortgenai`). Any of
these dirs missing is silently skipped, so partial setups still produce a
valid table.

## 4. Run

```sh
# Optional: override defaults shown here.
export LLAMACPP_BIN=~/baselines/llama.cpp/build/bin   # dir containing llama-bench
export GGUF_DIR=~/baselines/gguf                      # dir containing *-q8_0.gguf
export ORTGENAI_DIR=~/baselines/ortgenai              # dir containing per-model ORT-GenAI subdirs
export ORTGENAI_IMAGE=ortgenai-bench                  # podman image tag

cargo run --release -p bench-llm                       # 1 warmup + 3 measured iters (~3 min)
cargo run --release -p bench-llm -- --quick            # 1 warmup + 1 measured iter (debug)
cargo run --release -p bench-llm -- --filter mynn      # only rows whose label contains "mynn"
```

Outputs (gitignored): `bench/llm/raw/<run>.{log,vram.txt,rss.txt}` and
`bench/llm/results/SUMMARY.md`.
